# midimittr 改善ロードマップ

本ドキュメントは、`midimittr` プロジェクトのコード品質、保守性、および安定性を向上させるための段階的な改善計画をまとめたものです。

## 目的
- テスタビリティの向上とバグ混入の防止。
- レガシーな Objective-C コードの Swift 化による安全性確保。
- モダンな iOS 開発パターン（MVVM等）の導入による疎結合化。

---

## フェーズ 1: 安定化とテスト基盤の構築 (短期)
**目標:** 現状の動作を破壊せずに、安全にコードを変更できる環境を整える。

### 1.1 ユニットテストの導入
- **課題:** 現在、有効なテストコードが一切存在しない。
- **アクション:**
    - `XCTest` を用いて `MIDIController` の主要ロジック（デバイスリストの管理、選択状態の保持）に対するテストを作成する。
    - ルーティングロジックのモック化を行い、仮想 MIDI メッセージが正しく転送されるかを検証可能にする。

### 1.2 危険なグローバル変数の排除
- **課題:** `MIDIController.mm` 内の `thisClass` 変数による自己参照。
- **アクション:**
    - `MIDIController` をシングルトンパターン（`shared` インスタンス）にするか、DI（依存性注入）を整理して適切なライフサイクル管理を行う。

### 1.3 エラーハンドリングの刷新
- **課題:** `NSAssert` による強制終了リスク。
- **アクション:**
    - `NSAssert` を適切なエラー通知（`Error` 型の返却や Delegate 経由の通知）に置き換える。
    - ユーザーに対して「MIDIデバイスのアクセス権限不足」などをアラートで表示する仕組みを導入。

---

## フェーズ 2: モダナイゼーション (中期)
**目標:** 技術スタックを最新化し、開発効率を向上させる。

### 2.1 MIDIController の Swift 化
- **課題:** CoreMIDI のポインタ操作が Objective-C で行われており、メモリ安全性が低い。
- **アクション:**
    - `MIDIController` を Swift で書き直す。CoreMIDI の Swift ラッパーを活用し、型安全な MIDI メッセージ処理を実現する。
    - C 言語スタイルのマクロや関数を Swift の型安全な関数に置き換える。

### 2.2 バックグラウンド処理の正規化
- **課題:** 無音 MP3 再生によるバックグラウンド維持（ガイドライン違反のリスク）。
- **アクション:**
    - `Audio`, `Bluetooth-central`, `Bluetooth-peripheral` のバックグラウンドモードを適切に設定し、Apple のガイドラインに適合した形での維持方法を検討する。

### 2.3 依存関係管理の移行
- **課題:** Carthage による古い管理方法。
- **アクション:**
    - 可能であれば **Swift Package Manager (SPM)** への移行を検討し、外部ライブラリの管理をシンプルにする。

---

## フェーズ 3: アーキテクチャの刷新 (長期)
**目標:** スケーラブルで変更に強いコードベースの構築。

### 3.1 MVVM パターンの導入
- **課題:** View Controller がロジック（MIDIの状態管理など）を持ちすぎている。
- **アクション:**
    - `MIDIPortsViewModel` などを導入し、UI プレゼンテーションロジックを分離。
    - `Combine` または `Swift Concurrency` を使用して、MIDI デバイスの状態変化をリアクティブに UI へ反映する。

### 3.2 AppDelegate の責務削減
- **課題:** 画面遷移や依存関係の注入が `AppDelegate` に集中している。
- **アクション:**
    - `Coordinator` パターン等の導入により、画面遷移ロジックを専用のクラスに分離。

---

## 進捗確認（定義）
各フェーズの完了条件は以下の通りとする。
- **フェーズ 1 完了:** 主要ロジックのテストカバレッジが 50% を超え、クラッシュを伴う Assert が排除されていること。
- **フェーズ 2 完了:** `MIDIController` が Swift で完全に書き換えられ、警告なしでビルドできること。
- **フェーズ 3 完了:** UI ロジックが分離され、View Controller のコード量が大幅に削減されていること。
